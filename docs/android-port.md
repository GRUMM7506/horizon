# Порт на Android (arm64-v8a)

Документ форка: что нужно Horizon, чтобы работать на Android, что для этого изменено, как собрать и что ещё
не проверено. Апстрим Android не поддерживает; всё Android-специфичное спрятано за
`#[cfg(target_os = "android")]`, новым крейтом `crates/horizon-android` и папкой `android/`.

Ход работы по этапам: [PROGRESS.md](../PROGRESS.md).

## 1. Разведка

### Что уже есть в апстриме

Апстрим по частям переносит к себе код стороннего Android-порта
[Starling](https://github.com/starling-client/starling) (ветка `android`, см. `THIRD_PARTY_NOTICES.md`). В дереве
уже лежит чистая логика без единого обращения к ОС, покрытая тестами, но **нигде не подключённая к игре**:

| Файл (`crates/horizon-client-render/src/`) | Что делает |
|---|---|
| `touch.rs`, `touch/{layout,aim,draw}.rs` | Сенсорное управление: джойстик или D-pad, жесты камеры, кнопки, тап и удержание по миру, раскладки, размер и прозрачность кнопок, отрисовка в HUD. Пальцы превращаются в `PadState`, то есть в то же состояние, что даёт геймпад |
| `android_gamepad.rs` | Декодер геймпада из кодов Android (`KEYCODE_BUTTON_*`, `AXIS_*`) в `PadState`, выбор активного устройства ввода |
| `android_runtime.rs` | Глобальное состояние ввода на процесс: геймпады, режим ввода, keypad-профиль |
| `keypad.rs` | Профиль для кнопочных телефонов |

Порт подключает эти модули, а не пишет своё управление: так форк проще ребейзить, а когда апстрим подключит их
сам, конфликт будет в нескольких строках.

### Платформенно-зависимый код

**Запуск.** `horizon_game::main` → `horizon_guest_stack::prepare_main` → `entry::prepare` →
`horizon_mod_host::main_with` → `entry::start` → `game::run_with`.

| Место | Проблема на Android | Решение |
|---|---|---|
| `horizon-guest-stack/src/lib.rs` `prepare_main`, `inspect_current` | На Linux процесс перезапускает сам себя с большим стеком; на «прочих» ОС проверка стека возвращает ошибку и процесс завершается. Потоку игры нужно 136 МиБ стека (гостевой код модов, большие структуры) | Проверка стека для Android та же, что для Linux (`pthread_getattr_np`); поток `android_main` создаётся с нужным стеком (см. раздел 3) |
| `entry.rs` `prepare()` | Читает `argv` и `current_exe`; модуль `horizon_mod_package::holder` выключен вне Linux/macOS/Windows, крейт не собирается | Отдельный `prepare_android(args, game_dir, home)`: аргументы приходят от лаунчера |
| `launch_options.rs` `from_launch` | Ресурсы по умолчанию ищутся рядом с исполняемым файлом | Лаунчер всегда передаёт `--resources`, `--game-dir`, `--home` |
| `std::process::exit` при ошибках | Убивает процесс активности | Игра работает в отдельном процессе `:game`; лаунчер показывает хвост лога, если игра завершилась не сама |
| `horizon-mod-wasm/src/module_cache.rs` | Компиляция WASM-модов запускает дочерний процесс из `current_exe` | Не поддерживается: моды на Android пока не работают (известное ограничение) |
| `desktop.rs`, `pad_menu.rs` (`xdg-open`) | Открытие ссылок и папок | Не работает, не падает |

**Окно и поверхность.** winit 0.30.13, один цикл событий на процесс; три места создают его через
`EventLoop::new()`: `game/runtime/resource_loader.rs` (обычный старт), `loading_screen.rs` (синхронный путь),
`no_resources.rs` (нет ресурсов). На Android циклу нужен `AndroidApp`. Обработчиков `ApplicationHandler` четыре:
`App` (экран загрузки → игра), `Split` (разделённый экран), `Game`, `Missing`. Окно создаётся в `resumed`, но
`suspended` не реализован нигде, а повторный `resumed` игнорируется. В `Renderer` (`horizon-client-render/src/gfx.rs`)
уже есть `recreate_surface()` (на том же устройстве) и флаг `suspended`, при котором кадр пропускается: этого
достаточно, чтобы отпускать поверхность при сворачивании и создавать новую при возврате.

Расширения winit, которых нет на Android: `platform::scancode`, `platform::modifier_supplement`
(`horizon-client-input/src/keybinds.rs`, `game/runtime/window_handler.rs`), `platform::wayland` (уже за
`cfg(target_os = "linux")`, а Android это не `linux`).

**Графика.** wgpu 30.0.1 со своей копией `wgpu-hal`. Порядок бэкендов вне Windows: Vulkan, затем GL. Все
возможности устройства запрашиваются по маске `adapter.features()`, лимиты берутся у адаптера, так что жёстких
требований десктопного уровня нет. Обязательны: `Depth32Float` с чтением, достаточное число слоёв массива
текстур, формат поверхности. Для Adreno в `gfx/cull.rs` уже есть отдельная ветка.

**Ввод.** `WindowEvent::Touch` не обрабатывается. Клавиатура и мышь идут через
`Game::handle_window_event_inner` (`game.rs`); геймпад читается в `game/interface/pad/mod.rs` (`poll_pads`),
куда `horizon-ctl pad` уже подмешивает виртуальный пад. Текст приходит через `Ime::Commit` и `KeyEvent.text`.
winit на Android с GameActivity не передаёт текст экранной клавиатуры (событие `TextEvent` он отбрасывает), а
оси геймпада превращает в ложные касания.

**Звук.** `cpal` 0.16 в `horizon-client-render` (фича `audio`); у cpal есть бэкенд AAudio, зависимость уже в
`Cargo.lock`. Формат и частота берутся по умолчанию у устройства, нет устройства: игра молчит и работает.
Приостановки потока нет. Декодер (`symphonia`) на чистом Rust. Диктор (`horizon-narrator`) на неизвестной ОС
просто выключен.

**Файлы.** Крейтов `dirs`/`home` нет. Домашняя папка: `--home`, затем `HORIZON_HOME`, затем `XDG_DATA_HOME`/`HOME`.
Папка игры (`--game-dir`) становится рабочим каталогом процесса, `options.txt` и сохранения лежат в ней.
Масштаб интерфейса и дальность прорисовки хранятся в `options.txt` (`guiScale`, `renderDistance`); для дальности
есть и флаг `--render-distance`.

**Архитектура процессора.** x86-специфики без запасного пути нет: macOS ARM поддерживается официально, так что
у всего (`jmath`, AES в протоколе, раскрутка стека в `horizon-threads`) есть ветка aarch64 или переносимая.
`horizon-threads` уже знает про `target_os = "android"` (сигналы, память процесса, дамп стеков).

**Зависимости, которые не собираются под Android.**

| Зависимость | Что с ней |
|---|---|
| `arboard` (буфер обмена) | Нет бэкенда: вынесена из Android-сборки, копирование работает внутри игры |
| `winit` | Требует выбрать `android-game-activity` или `android-native-activity` |
| `hidapi` (`horizon-dualsense`), `gilrs` | Фича `controllers`: на Android выключена, геймпад идёт через Java и `android_runtime` |
| `mimalloc` | Собирается NDK; можно заменить на системный (`system-allocator`) |
| `wasmtime` (`horizon-mod-host`) | Собирается, но моды не запускаются (см. выше) |

игра уже получает от клавиатуры, мыши и геймпада.

## 3. Как это устроено

**Процесс и поток.** `HorizonActivity` объявлена в манифесте с `android:process=":game"`: игра живёт в своём
процессе. Игра инициализируется один раз на процесс (хуки, логи, `OnceLock`), а при ошибках зовёт
`std::process::exit`, поэтому когда `android_main` возвращается, библиотека закрывает активность и завершает
процесс (`_exit`), а лаунчер остаётся в своём. Результат запуска пишется в `horizon/last-exit.txt` (`running`,
`ok`, `error`, `panic`); лаунчер читает его и показывает хвост лога, если игра завершилась не сама.

**Стек.** Игровому потоку нужно 136 МиБ стека, а glue-код android-activity создаёт поток `android_main` на C с
размером по умолчанию (1 МиБ). Цикл событий обязан работать именно на этом потоке (его `ALooper`), поэтому
библиотека линкуется с `-Wl,--wrap=pthread_create` (`crates/horizon-android/build.rs`): все вызовы
`pthread_create` внутри `.so` идут через `__wrap_pthread_create` (`stack.rs`), и тот единственный, что просит
отсоединённый поток стандартного размера, получает большой стек. Вендорить android-activity ради трёх строк не
пришлось. Фактический размер стека печатается первой строкой лога.

**Аргументы и пути.** Kotlin выставляет переменные окружения до загрузки библиотеки (`Os.setenv` в
`HorizonActivity.onCreate` перед `super.onCreate`): `HORIZON_ANDROID_DIR` (папка
`getExternalFilesDir()/horizon`), `HORIZON_ANDROID_ARGS` (аргументы, по одному на строку), `TMPDIR`, `HOME`,
настройки сенсорных кнопок. Лаунчер всегда передаёт `--game-dir`, `--home`, `--resources`, `--name` и, если
задан адрес, `--server`.

**Блокировки файлов.** Папка игры лежит на общем хранилище, которое Android отдаёт через FUSE, и `flock` там
отвечает ENOSYS (это показал дымовой тест на эмуляторе). Игра блокирует `session.lock` мира, свой лог и кэш
паков и неудачную блокировку понимает как «занято другим экземпляром», так что ни один мир не открылся бы.
Библиотека линкуется ещё и с `--wrap=flock` (`locks.rs`): на хранилище без блокировок блокировка считается
полученной. На устройстве игра одна и в одном процессе, поэтому защищать нечего; в логе об этом одна строка.

**Жизненный цикл.** winit зовёт `resumed`, когда у активности появляется окно, и `suspended`, когда оно
уходит. Первый `resumed` создаёт окно и рендерер, как на десктопе. `suspended` зовёт `Renderer::window_lost`:
останавливает генерацию кадров, ждёт очередь, бросает поверхность (пока окно ещё живо) и ставит `suspended`,
так что кадры пропускаются; устройство и всё загруженное остаются. Следующий `resumed` зовёт `window_restored`:
новая поверхность на том же устройстве и `resize` под текущий размер (экран мог повернуться). Звук ставится на
паузу и снимается с неё там же. Пока игра свёрнута, мир не тикает; одиночная игра встаёт на паузу сама по
потере фокуса, как на десктопе.

**Экран.** Активность в альбомной ориентации (`sensorLandscape`, оба направления), полноэкранная
(системные панели скрыты, появляются свайпом). По умолчанию окно не заходит под вырез экрана
(`LAYOUT_IN_DISPLAY_CUTOUT_MODE_NEVER`), так что интерфейс игры целиком в безопасной зоне; в лаунчере есть
переключатель «рисовать под вырезом». Когда открыта экранная клавиатура, поверхность укорачивается на её
высоту, и строка чата остаётся видна.

**Касания.** `WindowEvent::Touch` перехватывается до обработки игрой (`android_window_event`):

- В мире (указатель «захвачен») пальцы идут в `TouchControls` апстрима: левый джойстик, свайп по экрану
  поворачивает камеру, кнопки прыжка, приседания, бега, атаки, использования, инвентаря, чата, паузы, F3 и F5.
  Их состояние (`PadState`) подмешивается в `poll_pads` как ещё один геймпад, поэтому дальше работает тот же
  код, что и для контроллера. Тап по хотбару выбирает слот. Тап по миру атакует, удержание использует предмет;
  переключатель в лаунчере меняет схему на «тап использует, удержание ломает».
- Над любым экраном (меню, инвентарь, чат) один палец работает как мышь (`touch_pointer`): тап это щелчок,
  вертикальный свайп прокручивает, горизонтальное движение или удержание 150 мс начинает перетаскивание.
- Кнопка «Назад» и жест «назад» приходят как Escape.

**Текст.** winit с GameActivity отбрасывает текст экранной клавиатуры, поэтому клавиатуру показывает сама
активность: невидимый `KeyboardSink` со своим `InputConnection` сравнивает буфер клавиатуры с уже отправленным
и шлёт игре разницу (текст и backspace) через JNI. Игра вставляет её в поле с фокусом тем же путём, что и
встроенная клавиатура контроллера (`pad_osk_output`). Кириллица и автозамена работают, потому что передаётся
итоговый текст, а не коды клавиш.

**Физические устройства.** Клавиатура идёт через winit как обычно. Мышь и геймпад перехватывает
`HorizonActivity` (иначе winit принял бы их за пальцы): мышь становится событиями курсора и кнопок, в мире
захватывается (`requestPointerCapture`) и поворачивает камеру; геймпад отдаётся декодеру апстрима
(`android_runtime::gamepad_event`). Когда играют контроллером, клавиатурой или мышью, от сенсорных кнопок
остаются только служебные (чат, пауза, F3, F5).

**Звук.** cpal 0.16 открывает AAudio сам; правок, кроме паузы при сворачивании, не понадобилось.

## 4. Сборка

Нужны: Rust из `tools/ci/rust-version` с целью `aarch64-linux-android`, Android SDK (platform 35,
build-tools 35.0.0), NDK 27.2.12479018, JDK 17 или 21, Gradle 8.13+ (в репозитории нет `gradle-wrapper.jar`:
`tools/check_public_tree.py` отклоняет любые `.jar`; сделать его себе можно командой `gradle wrapper` в
`android/`).

```sh
rustup target add aarch64-linux-android
cargo install cargo-ndk --version 4.1.2 --locked
export ANDROID_HOME=/путь/к/sdk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018

# Движок сам по себе (rlib):
cargo ndk -t arm64-v8a --platform 26 build -p horizon-client --release

# Библиотека игры, сразу в папку лаунчера:
cargo ndk -t arm64-v8a --platform 26 -o android/app/src/main/jniLibs build -p horizon-android --release

# APK:
cd android && gradle :app:assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
```

`--release` включает thin LTO и долго собирается; для итераций есть `--profile fast` (минут 13 с нуля на
4 ядрах).

APK подписан отладочным ключом из `android/debug.keystore` (пароль `android`). Ключ лежит в репозитории
намеренно: локальные сборки и сборки CI подписаны одинаково, новый APK ставится поверх старого, и папка игры на
телефоне (ресурсы и сохранения, которые система удаляет вместе с приложением) остаётся. Он ничего не защищает;
для публикации нужен свой.

**CI.** `.github/workflows/android.yml` на каждый push в `android-port`:

- задача `apk` собирает библиотеку и APK и выкладывает артефакт `horizon-android-debug-apk`;
- задача `emulator` собирает ту же библиотеку под x86_64 и гоняет `android/smoke-test.sh` на эмуляторе с
  программным Vulkan: игра стартует без ресурсов (её экран «нет ресурсов», то есть собственное окно, рендерер и
  цикл событий движка), получает касания, дважды уходит по «Домой» и возвращается. Тест проверяет, что поток
  получил стек 136 МиБ, что игра услышала остановку активности и получила окно обратно, и что процесс всё это
  пережил. Логи и скриншоты лежат в артефакте `horizon-android-smoke-test`. Настоящий GPU и саму игру он не
  проверяет.

Собрать APK для эмулятора локально: `cargo ndk -t x86_64 ...` и `gradle :app:assembleDebug -Phorizon.abi=x86_64`.

## 5. Установка

1. На ПК подготовить ресурсы из своей копии Minecraft 26.3: `horizon-prepare` (см. `docs/native-client.md`).
   Получится папка `.local/` (нужна `.local/horizon-client/26.3/` с файлом `horizon-resources.json`).
2. Установить APK, запустить лаунчер один раз (он создаст папку игры).
3. Скопировать `.local` в `Android/data/dev.horizonport.android/files/horizon/` по USB, либо упаковать `.local`
   в zip и импортировать кнопкой в лаунчере. Из `.local` игре нужна только папка `horizon-client`; остальное
   (jar-файлы, декомпилированные исходники) служит подготовке и на телефоне не нужно.
4. Указать ник, при желании адрес сервера, и нажать «Играть».

Сохранения (`saves/`), `options.txt`, логи (`logs/latest.log`, `logs/android-output.log`) и отчёты о сбоях
(`crash-reports/`) лежат в той же папке. Раскладка сенсорных кнопок читается из `horizon-touch.json` там же
(формат `touch::Settings`), если файл есть.

## 6. Известные проблемы и ограничения

- **Моды не работают.** Компилятор WASM-модулей запускается дочерним процессом из исполняемого файла игры
  (`horizon-mod-wasm/src/module_cache.rs`), а у приложения Android такого файла нет. Нативные моды собирает
  десктопный лаунчер. Без установленных модов этот код не выполняется.
- **Только офлайн-ник.** Входа в аккаунт Microsoft в лаунчере нет, поэтому на серверы с `online-mode=true` не
  пустит. Локальная сеть и серверы без проверки аккаунта доступны.
- **Действия идут по прицелу.** Схемы апстрима «тап по месту касания» требуют, чтобы игра целилась в точку
  касания; склейка этого не делает и включает прицел принудительно.
- **Нет экрана настроек сенсорного управления в игре.** Размер и прозрачность задаются в лаунчере, раскладку
  можно менять только файлом `horizon-touch.json`.
- **На экране загрузки нельзя печатать.** Пока ресурсы грузятся, меню уже отвечает на касания, но клавиатуру
  не показывает; после загрузки всё работает.
- **Свёрнутая игра не тикает.** На удалённом сервере через полминуты в фоне соединение оборвётся по таймауту.
- **Буфер обмена Android не подключён**: копирование и вставка работают только внутри игры. Ссылки и папки из
  игры не открываются (`xdg-open`).
- **Нет вибрации геймпада, диктора, Discord-статуса** и остальных частей `horizon-official` (порт собирает
  `horizon-game`).
- **Только arm64-v8a, Android 8.0+ (API 26), только альбомная ориентация.**
- **APK около 120 МБ**: библиотека игры лежит в нём без сжатия, чтобы система отображала её прямо из APK.
- Предупреждение компилятора `field data is never read` в `horizon-mod-package` появляется только при сборке под
  Android: это код апстрима, которым на Android никто не пользуется.

## 7. Что не проверено без реального устройства

В песочнице нет ни устройства, ни эмулятора с аппаратным ускорением. Локально проверено, что всё собирается и
линкуется, модульные тесты логики указателя, и сброс с восстановлением поверхности рендерера на десктопе с
программным Vulkan (lavapipe, экран «нет ресурсов»). Запуск на Android до экрана «нет ресурсов» и сворачивание
проверяет дымовой тест в CI на эмуляторе, тоже с программным Vulkan и без игровых ресурсов. Всё ниже нужно
пройти на телефоне.

### Как прислать отчёт с телефона

Порт рассчитан на то, что его доводят по логам с настоящих устройств, без компьютера под рукой:

1. Если проблема в управлении (кнопка не срабатывает, палец уходит не туда), включите в лаунчере «Подробный лог
   ввода» и воспроизведите её: каждое касание, клавиша и то, что из них получила игра, попадут в лог.
2. В лаунчере, в блоке «Диагностика», нажмите «Отправить отчёт». Лаунчер соберёт файл `android-report.txt` и
   предложит отправить его любым приложением. «Показать отчёт» показывает его конец на экране.
3. Приложите пару слов: что делали и что произошло.

В отчёте: модель устройства, чип, версия Android, память, экран, версии Vulkan и OpenGL ES, настройки лаунчера,
итог прошлого запуска и конец каждого лога: `logs/latest.log` (лог игры: какой GPU и драйвер выбраны, остановка
и возврат активности, размер окна, фокус, клавиатура), `logs/android-output.log` (stdout и stderr: аргументы
запуска, размер стека потока, сообщения о панике), последний отчёт о сбое из `crash-reports/` и строки logcat
самого приложения (там остаётся след падения в нативном коде, например в драйвере GPU). Тот же файл лежит в
папке игры, если удобнее забрать его по USB; с компьютером работает и `adb logcat -s Horizon`.

Отчёт пишется из лаунчера, поэтому он есть и тогда, когда игра не запустилась вовсе.

**Запуск**

- [ ] Игра стартует из лаунчера; первая строка `android-output.log` показывает `thread stack 136 MiB` (если там
      1 МиБ, подмена `pthread_create` не сработала на этой версии Android).
- [ ] Экран загрузки, затем главное меню. Время загрузки ресурсов с внешнего хранилища.
- [ ] «Выйти из игры» возвращает в лаунчер; после сбоя лаунчер показывает блок «Прошлый запуск».
- [ ] Устройство с 16-КБ страницами памяти (Android 15+): библиотека загружается.

**Рендер (на каждом GPU отдельно: Adreno, Mali, PowerVR, Xclipse)**

- [ ] Vulkan-устройство открывается, нет отката на OpenGL ES (строка рендерера в `latest.log`).
- [ ] Нет артефактов: мир, вода, небо, частицы, интерфейс, текст.
- [ ] Хватает лимитов драйвера (размер текстур, слои массива текстур для атласа блоков).
- [ ] FPS, нагрев и потребление памяти на дистанции 4, 8, 12 чанков; нет ли вылетов по памяти.

**Жизненный цикл**

- [ ] Кнопка «Домой» и возврат: картинка возвращается без падения, много раз подряд.
- [ ] Блокировка и разблокировка экрана; входящий звонок; шторка уведомлений.
- [ ] Поворот на 180°; разделённый экран и складные устройства (смена размера окна).
- [ ] Сворачивание во время загрузки мира и на экране загрузки.
- [ ] Мир сохранён, если система убила свёрнутую игру.

**Звук**

- [ ] Звук есть, задержка приемлема, нет треска.
- [ ] При сворачивании замолкает, после возврата продолжается.
- [ ] Подключение и отключение наушников (в том числе Bluetooth) на ходу.

**Сенсорное управление**

- [ ] Джойстик, поворот камеры (чувствительность), одновременно движение, камера и прыжок.
- [ ] Кнопки: прыжок, присесть, бег, атака (удержание ломает блок), использовать, инвентарь, чат, пауза, F3, F5.
- [ ] Тап по миру атакует, удержание использует; переключатель в лаунчере меняет схему.
- [ ] Тап по слоту хотбара выбирает его.
- [ ] В меню: нажатие кнопок, прокрутка списков свайпом, ползунки, перетаскивание предметов в инвентаре.
- [ ] Размер и прозрачность кнопок из лаунчера применяются.
- [ ] Жест «назад» закрывает экран или ставит паузу.

**Текст**

- [ ] Чат: латиница, кириллица, эмодзи, backspace, отправка кнопкой клавиатуры.
- [ ] Клавиатуры с автозаменой и вводом свайпом (Gboard, SwiftKey, клавиатура Samsung).
- [ ] Таблички, книга, название мира, адрес сервера, поиск в творческом инвентаре.
- [ ] Клавиатура не закрывает строку ввода; после скрытия возвращается по касанию.

**Физические устройства**

- [ ] USB- и Bluetooth-клавиатура.
- [ ] Мышь: курсор в меню, кнопки, колесо, захват и поворот камеры в мире.
- [ ] Геймпад: стики, триггеры, крестовина, кнопки; сенсорные кнопки при этом прячутся.

**Файлы**

- [ ] Ресурсы находятся после копирования `.local` по USB.
- [ ] Импорт zip на 1 ГБ и больше: прогресс, отмена, нехватка места.
- [ ] Создание, сохранение и повторное открытие мира (в том числе блокировка `session.lock` на внешнем хранилище).
- [ ] `options.txt`: дистанция и масштаб интерфейса из лаунчера применяются, изменения из игры видны в лаунчере.

**Экран и сеть**

- [ ] Вырез: по умолчанию интерфейс не заходит под него; с переключателем заходит.
- [ ] Вход на сервер из поля лаунчера и из игры; игра по локальной сети.
- [ ] Лаунчер на устройстве без Vulkan 1.1 показывает предупреждение.
